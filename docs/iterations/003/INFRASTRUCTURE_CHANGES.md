# Infrastructure changes and rationale

Starting revision: `a0f41bfc99c9a991879e3047beb3739f98d8ad6c`. Functional screens, FastEmbed retrieval and verification algorithms are retained. Changes target deployment boundaries and release operations.

- Replaced the incomplete hosted override with a standalone six-service definition. Removed inherited local DB dependencies, developer hostnames, public processor/editor ports and unnecessary public webhook ingress. Added isolated backend/source/runner bridges, bounded resources/logs, non-root/read-only services, shutdown periods and durable n8n/model/TLS volumes.
- Added the optional loopback-only free Funnel ingress overlay and a distinct eight-service local rehearsal overlay. Existing Iteration 002 volumes, database records and n8n encryption keys are never reset or reused for rehearsal.
- Kept exact n8n/runner versions compatible at 2.42.6; reviewed Caddy2.11.2 and PostgreSQL17.9 images. Linux ARM64 execution and amd64 image manifests are separate evidence. Python3.12.15 dependencies remain locked.
- Added safe production input/topology validation, ignored environment preparation, workflow publication/hash manifests, database connectivity/version/role/TLS checks, rolled-back permission probing, backup/empty-destination restore, public smoke tests, source checksums and local release rehearsal scripts.
- Added explicit administrator-controlled private origins rather than enabling development trust switches in production. The fixed private synthetic source works without a laptop and retains its data classification.
- Enforced hosted PostgreSQL with verified TLS; migration startup remains transactional/additive/advisory-locked. Older releases now refuse a newer schema ledger instead of silently writing to it.
- Added authenticated on-demand database readiness, one startup database check, sanitized persistence errors and structured operational metadata. Recurring container checks use liveness so they do not prevent Neon free-tier sleep.
- Added an in-process login throttle and durable global/per-workspace source-run limits. Existing model budgets remain global; production generation additionally requires explicit free-tier confirmation. The owner said billing status is unknown, so Gemini stays disabled.
- Processor no longer needs the actual Gemini API key; n8n receives provider credentials only as encrypted credential objects through temporary stdin/tmpfs import. Explicit release environment files override developer `.env` values, preventing cross-environment encryption-token mismatches.
- Expanded security scanning to configured release/rehearsal secret values, updated CI with deployment/gateway/checksum checks, and kept automatic deployment absent.

Actual rehearsal found defects that syntax-only preparation missed: comma-containing tmpfs options needed quoting; n8n required a writable static cache; Caddy's image file capability conflicted with an empty capability bounding set; executable host-mounted database initialization was unreliable; repeat publication initially included its own manifest; explicit env-file precedence needed protection from Python dotenv loading; and the Hugging Face/Xet download cache needed a persistent writable HF_HOME despite an already configured embedding cache. Those were corrected and exercised. Local PostgreSQL backup also needed network-scoped restore preflight and explicit local TLS handling. No failed attempt was relabeled as success.

The primary hosting recommendation was revised when the owner specified a hard $0 budget: no paid VPS/container plan, no paid disk, no temporary credits and no automatic upgrade. Conditional Oracle Always Free + Neon Free + Personal Funnel is prepared; capacity/account/cost eligibility remain release gates.
