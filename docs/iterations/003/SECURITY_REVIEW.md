# Security review — controlled synthetic public portfolio

Scope includes current tracked/untracked release files, available Git history, workflow graphs, Docker input/context, proxy routes, source validation, authentication, exports, failure logs and release scripts. The scanner checks known configured companion/release/rehearsal secret values and selected credential patterns without printing values. Historical Mailtrap account/inbox identifiers remain in old Git blobs; current evidence is redacted. A pattern/value scan cannot guarantee the absence of an unknown secret. No history rewrite or automatic credential rotation is performed.

## Boundaries

- Shared strong password gates the app; random workspace capabilities scope saved histories/reviews/exports. Server-side owner checks remain. Capabilities are private bearer credentials; they are not employee identities/tenant roles. Password attempts have a shared in-process throttle; it resets on app restart and can be abused to temporarily deny login. Restrict reviewer distribution and replace with OIDC/SSO if the product expands.
- Global/per-workspace source limits are persisted. Model requests have global daily budgets plus explicit free-tier confirmation; the owner instructed Gemini remain disabled. Agent iterations/timeouts are bounded; daily investigations do not equal individual provider turns. No automatic paid fallback, provider purchase, billing change or unbounded retry was added.
- No provider/database/admin credential goes to the browser. APIs require server-side headers. n8n editor, broker, processor, database and fixture have no public production ports. Public proxy blocks internal paths; actual local requests verified404. Direct TLS and Funnel ingress have separate explicit port settings.
- Private origins are administrator-controlled exact matches; operators cannot supply arbitrary source URLs. Existing HTTPS validation blocks unsafe source targets; the private synthetic source is the named service only. Container networks provide segmentation; they do not constitute a complete provider-domain egress firewall.
- Evidence/user content remains untrusted model input. Only three read-only tools exist; observed results must match the permitted snapshot and citations must have been observed. No source can grant tool permissions or promote deterministic records.
- Python/n8n/runner/gateway are non-root, use read-only roots with minimal writable paths, drop capabilities and avoid Docker socket/host networking. Caddy's file capability was explicitly removed to work with the empty bounding set. External runner has no business secrets or state mounts. Images are pinned and architecture-reviewed; automated CVE certification was not claimed.
- Hosted PostgreSQL requires verified TLS and a dedicated non-superuser role. Additive migrations are locked and reject a future schema. Restore requires an explicitly named empty destination. Secrets/backups are ignored and permission-restricted; off-host backups must also be encrypted.
- Structured operational logs whitelist correlation/stage/status/duration fields and omit bodies, owners and tokens. Uvicorn access logging is disabled; proxy access-body logging is absent. Public evidence is sanitized. Health checks reveal no credentials and public internal-health paths are denied.

## Remaining release risks

Free-plan capacity/reclamation, Neon quota/cold starts, Funnel beta/bandwidth limits, unaudited cloud firewall/SSH policy, account eligibility and hosted certificate acceptance remain unresolved. Gemini account billing state is unknown, so generation is intentionally disabled. The stopped n8n backup is complete but replacement-host restoration is still pending. Capability loss cannot be recovered without a saved key. Synchronous workflows have conservative interruption detection, not a durable queue or automatic worker recovery. A public reviewer can consume shared quotas if given the password; this is a controlled-access demo, not commercial multitenancy.

Before provisioning, verify account-level $0 entitlements and no automatic upgrades. Before public release, confirm new-project identity, key storage/backup, reviewer access, retention, actual host network rules, TLS, model-free-tier state and smoke/restore checks. If a genuine credential is discovered in publication, revoke/rotate that credential through its owner console and assess exposure; account/inbox IDs alone are not an API key. Do not change original EventOps or unrelated infrastructure.
