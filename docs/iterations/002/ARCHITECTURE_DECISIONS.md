# Architecture decisions — Iteration 002

- Keep structured-row FastEmbed/NumPy retrieval: measured curated quality is strong for this small corpus; a vector database adds no demonstrated benefit. Explicit event references now precede inherited context; vague/multiple references clarify without a model call.
- Add a versioned 30-case evaluation set with expected sources/fact aliases, Recall@5/MRR, clarification/abstention checks and separate curated factual/citation evaluation. A numeric/action-claim guard is conservative, not a proof of entailment. No additional judge model is added to ordinary requests.
- Preserve the generic audit snapshot table because the UI restores whole bounded executions. Add revisions, a migration ledger and a dedicated investigation-claim table where uniqueness actually matters. Optimistic compare-and-swap prevents lost updates; reviews update the snapshot and insert the audit note in one transaction. SQLite serializes migration startup; PostgreSQL uses an advisory transaction lock.
- Keep n8n as orchestrator. Each source read/parsing failure is isolated, outcomes are retained, and source checkpoints bind a run to a real execution ID. A separate diagnostic graph exercises real HTTP error behavior without pretending test routes are external providers.
- Replace n8n environment expressions with generated administrator-controlled processor URLs and block node environment access. Credentials remain separate encrypted n8n objects.
- Preserve read-only Gemini tools. Expand explanations with evidence-linked findings/conflicts, uncertainties and advisory actions. Compare tool records with the permitted snapshot, validate nested citations, and reserve investigations atomically by owner/run/intent/evidence hash. Repeated identical requests reuse results rather than consume budget.
- Reconcile uncertain delivery from persisted reservation/checkpoints and optional owner-bound n8n metadata. Staleness means intervention, not completion or durable recovery. No queue/worker recovery claim is introduced.
- Add a controlled event source served independently over actual HTTP and retain genuine Mailtrap reads. This is explicitly synthetic local transport, not a fabricated third-party API or a hosted integration. External holidays remain a separate reference scenario.
- Additional knowledge is protected, workspace scoped and non-authoritative. Original identity/reference documents never change. Supplemental versions are fingerprinted, reindexed and auditable; public deployment keeps administration disabled.
- Recommend one private container provider/network plus a dedicated durable PostgreSQL deployment. The full local Linux topology is tested; public hosting, domains, billing and managed DB entitlements are separate approvals and acceptance.
