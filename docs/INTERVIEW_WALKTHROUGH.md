# A focused 5–7-minute companion demonstration

Keep the main 45-minute interview centered on the submitted full-stack application. Use this companion as evidence of implementation versatility, not as a replacement submission or a claim that one framework is always better.

## Before the interview

Start the local processor, Streamlit and published n8n workflows. Run the regression suite once. Confirm the three source outcomes, model availability and example sandbox messages. Save the workspace access key and have a persisted completed execution ready. Do not depend on live quotas or a public deployment that has not been verified. The evidence files are a transparent backup, not a fake live run.

## 0:00–0:45 — Business problem and second implementation

“Event operations information is fragmented across schedules, email registrations and reference records. The system retrieves authoritative knowledge and automatically compares incoming claims while keeping uncertain decisions reviewable. My submitted version uses React, FastAPI, LangGraph and PostgreSQL. I built this independent Streamlit/n8n version to show how I would deliver the same internal-tool problem with different constraints.”

Open Overview. Explain that the sample identities are synthetic and external holiday data is not participant data.

## 0:45–2:00 — Grounded knowledge assistant

Ask: “What are the check-in rules for EVT-101?” Show the actual `POL-003` record and cosine similarity. Explain structured rows as retrieval units, local 384-dimensional FastEmbed vectors, metadata filtering and a small fingerprinted NumPy index.

Ask: “And how early must I cancel it?” Expand retrieval inspection. Show inherited event context and `POL-002`. Distinguish deterministic query transformation, retrieved evidence, Gemini's generated answer and citation validation. If Gemini is unavailable, state that the live model step failed and show the prior recorded model response transparently.

## 2:00–3:30 — Visual autonomous workflow

Open Agent Workspace and the real n8n verification graph. Trigger once if providers are healthy; otherwise open the saved actual execution and explain its timestamp. Show request ID and n8n execution ID. Explain the authenticated webhook, replay branch, real Calendar/Web HTTP nodes, bounded Mailtrap adapter, individual outcomes, aggregate and distinct processing primitives.

“The visual platform owns orchestration. Python owns testable parsing and authoritative comparison. There is no backend endpoint that secretly performs the whole pipeline.”

## 3:30–4:45 — Decisions, duplicates and evidence

Open Verification Results. Show Ada's verified record and the retained duplicate inputs. Show Lindi's inactive directory state and mismatched submitted name. Inspect raw source evidence and reference matches. Explain why the holiday observations remain incomplete and why a completed workflow does not mean every participant is verified.

Download all-record and verified-only CSVs. Reopen the same run from Execution History. Explain durable local storage versus ephemeral hosted filesystem; preserve the workspace key.

## 4:45–5:45 — Genuine model-assisted agent

Open Gemini analyst. Ask it to explain why Ada passed and Lindi failed, grounding the explanation in references and raw evidence. Show the actual AI Agent node, Gemini Chat Model connection and read-only tool connections. Open the saved tool calls and structured explanation.

“The model selected these tools during execution. The deterministic verification graph does not need the model. The model can explain findings but cannot override the authoritative rules.”

Mention the five-iteration and workflow-time bounds, structured validation, citation/tool checks, and synthetic-email-only demonstration guard. Do not present private chain-of-thought as evidence.

## 5:45–6:30 — Reliability and trade-offs

Show the test report and genuine execution IDs. Explain per-source failures, empty inboxes, provider errors, idempotency and uncertain webhook delivery. Review notes preserve human decisions separately from verification.

“Streamlit and n8n reduced interface/orchestration work for this small internal tool. For a large branded multi-user product, I would revisit custom frontend control, real identity/tenancy, queues, durable infrastructure and operational ownership. Building the same problem twice made those boundaries concrete.”

## Final factual boundary

This companion has real local execution evidence. Public hosting still requires approval for a new repository and independent hosted n8n/processor/durable database. Do not describe it as publicly deployed or commercially production-ready until those steps and hosted acceptance pass.
