Keep the main interview focused on the submitted full-stack project. Use this companion to show architecture selection and operational judgment.

Show a vague reference receiving clarification.

**2:00–3:30 — Real event processing.** Select Controlled assessment event and trigger once, or open a timestamped saved execution. Explain the independent synthetic HTTP Calendar/Web service and actual Mailtrap reads. Show actual n8n ID/checkpoints and source outcomes. The fixture's transport is real; it is not a claimed public event API.

**3:30–4:45 — Results and human review.** Inspect Ada's verified registration and retained duplicate inputs; Lindi's inactive/name rejection; wrong event and schedule/venue discrepancies; the incomplete identity. Explain workflow success versus record verification. Save a review reason/action without promoting status, exercise CSVs, and restore history. Then show the unavailable-Web run remaining partial.

**4:45–5:45 — Genuine Gemini analyst.** Show AI Agent, Gemini Chat Model and three read-only tools. Ask a focused investigation, inspect actual calls and evidence-linked findings/actions. Explain snapshot/citation validation, bounded usage and reused investigations. The recorded execution 24 rejected an invented shortened ID; that is a genuine failure caught by validation, not a valid answer.

**5:45–6:30 — Engineering and consulting judgment.** Show tests, real failure probes, concurrency/reconciliation, additive migrations and clean Linux topology. Explain why visual automation still needs code-level rules, why no queue recovery is claimed, and when a custom full-stack product is preferable.

End with the exact boundary: GitHub publication is complete; public application deployment/hosted CI acceptance are not. No deployment occurs in Iteration 002. Recommend the tested local stack for demonstration and one private container provider plus dedicated PostgreSQL for the approved hosting phase.
